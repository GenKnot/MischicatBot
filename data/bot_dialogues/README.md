# 机器人台词

运行时只查表，**不调用大模型**。`utils/bot_dialogue.py` 负责查找与校验，`tests/test_bot_dialogue.py` 会在 CI 里校验本目录所有文件。

> **用 AI 扩写台词，请直接用工具**：`scripts/dialogue_tool.py`（看缺口 → 出提示词 → 收稿校验合并），流程见 `data/CONTENT_GUIDE.md`。
> 下面是格式说明，工具生成的提示词里已经包含了这些规则。

## 文件

- `_default.json`：通用台词，**格子必须齐全**（18 个场景 × 4 个档位），别的原型缺什么就回退到它。
- `<原型>.json`：每个性格原型一份，文件名 = `archetype` 字段。原型清单见 `data/bot_archetypes.json`
  （豪爽 / 阴鸷 / 贪财 / 痴丹 / 迂腐 / 话痨 / 高冷 / 憨直）。**可以只写一部分**，没写的场景、档位自动回退。
- `豪爽.json` 是一份只写了几格的示例。
- **批次文件** `<原型>.<批次名>.json`（例如 `阴鸷.20261012-gpt.json`）：不同的 AI / 不同时间写的台词放各自的文件，互不覆盖，查找时自动合并（完全相同的句子去重）。
  文件里的 `archetype` 字段写原型名（不含批次名）。

## 格式

```json
{
  "archetype": "豪爽",
  "lines": {
    "greet": { "陌生": ["台词1", "台词2"], "熟识": ["…"], "至交": ["…"] },
    "gift_love": { "陌生": ["…"] }
  }
}
```

## 场景（`SCENES`）

| 场景 | 什么时候说 | 备注 |
|---|---|---|
| `greet` | 玩家点「搭话」 | 当天第一次聊 |
| `chat_again` | 今天已经聊过又点「搭话」 | 委婉地说「明天再来」 |
| `gift_love` | 收到**最喜欢的具体物品** | 惊喜 |
| `gift_like` | 收到喜欢的**类别** | 高兴 |
| `gift_neutral` | 收到无所谓的东西 | 客气 |
| `gift_dislike` | 收到讨厌的类别 | 尴尬 / 不悦 |
| `gift_hate` | 收到最讨厌的具体物品 | 生气 |
| `gift_limit` | 今天收礼已达 3 份 | 委婉谢绝 |
| `party_accept` / `party_refuse` | 邀请组队 答应 / 拒绝 | 拒绝是因为交情不够 |
| `dual_accept` / `dual_refuse` | 邀请双修 答应 / 拒绝 | 拒绝是因为交情不够 |
| `captive_release` | 真人攻击它打输了、被擒获，它决定**放走** | 居高临下 / 宽容 / 嘲讽，按原型 |
| `captive_rob` | 同上，它决定**劫走对方一点灵石** | 贪财 / 阴鸷最常见 |
| `captive_kill` | 同上，它决定**杀了对方**（这个开关默认关，台词先备着） | 冷酷 / 无奈 |
| `bot_robbed` | 它被真人**打劫**之后说的话 | 愤怒，这时它对玩家已是「仇视」档 |
| `bot_crippled` | 它被真人**废去修为**之后说的话 | 悲愤 |
| `bot_killed` | 它被真人**击杀**时的遗言 | 档位是被杀前的交情 |
| `recall_gift` | **追加在**搭话 / 送礼 / 组队 / 双修台词后面的一句回忆：提起玩家送过的礼物 | 偶尔出现；变量 `{item}` `{count}` |
| `recall_absence` | 同上：玩家隔了 3 天以上才又来 | 变量 `{days}` `{city}`；仇视冷嘲、至交惦记 |
| `recall_chat` | 同上：已经聊过很多次（≥5） | 变量 `{count}` |
| `recall_grudge` | 同上：玩家以前打劫 / 废过它 | 变量 `{count}`；别写成骂街 |
| `recall_together` | 同上：以前组过队 / 双修过 | 变量 `{count}`；双修要含蓄 |
| `recall_defeat` | 同上：玩家以前攻击它却输了 | 变量 `{count}` |

| `ambush_appear` | 拦路：它在野外拦住玩家时的第一句放话 | 变量 `{victim}`（被冒犯的人）；至交档是『不想对你出手』 |
| `ambush_demand` | 拦路：玩家逃不掉 / 打输后，它先开口要个交代 | 变量 `{victim}`；给玩家一个认错的机会，不是处决宣告 |
| `ambush_cripple` | 拦路：它决定废掉玩家修为时说的话 | 变量 `{victim}`；克制，不渲染血腥 |

`recall_*` 是**一句话接在另一句话后面**，所以要短、别再打招呼，像随口一提。

## 好感档位（`TIERS`，从低到高）

`仇视`（≤-30）、`陌生`、`熟识`（≥20）、`至交`（≥50）。同一句话在不同档位语气应该不同：陌生客气、熟识随意、至交亲近、仇视冷淡或敌意。

## 占位符

只允许 `{player}`（玩家道号）、`{bot}`（机器人道号）、`{item}`（礼物名，只用于 `gift_*` 场景）。`recall_*` 和 `ambush_*` 场景另有各自的变量（见上表）。其他花括号一律报错。

## 约束

- 每格至少 1 句，建议 3~5 句（同一句重复看到会腻）。
- 每句不超过 80 字，一句话，不要换行。
- 台词**只负责说**：不要在台词里许诺任何游戏结果（「送你一件宝物」「好感 +10」），给不给、涨多少由代码判定。
- 调侃可以，别羞辱玩家；不要出现真实人名、政治、成人内容。

## 给 AI 的提示词模板

> 你在为一款中文修仙文字游戏写 NPC 台词。性格原型是「{原型}」（{一句话描述}）。
> 请按下面 JSON 格式，为每个场景 × 每个好感档位各写 4 句台词，只输出 JSON。
> 场景含义：…（贴上面的场景表）。档位含义：…（贴档位说明）。占位符只能用 {player}、{bot}、{item}。
> 每句不超过 40 字，语气要体现原型，并且随好感档位变化。
